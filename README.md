# Market Insight — аналитика рынка артефактов STALCRAFT

Веб-приложение для анализа аукциона артефактов: живая лента выгодных лотов, каталог со
статистикой, история цен и графики, вотчлист и портфель сделок с расчётом прибыли.

Приложение **не автоматизирует игру**: нет OCR, чтения экрана и памяти, перехвата трафика и
автопокупок. Данные берутся только из официального API (или из встроенного симулятора).

## Структура

```
backend/   FastAPI + SQLite: источники данных, коллектор, аналитика, REST и WebSocket
frontend/  Next.js 14 + TypeScript + Tailwind: интерфейс на русском
```

Поток данных: источник API → коллектор → SQLite → аналитика → REST/WebSocket → фронтенд.
Любой слой заменяется отдельно: источник (`app/sources/`), хранилище (`app/models.py`),
метрики (`app/analytics.py`).

## Запуск

Бэкенд:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --port 8000
```

Фронтенд (в другом терминале):

```bash
cd frontend
npm install
npm run dev
```

Интерфейс: http://localhost:3000, API: http://localhost:8000/api/status,
документация FastAPI: http://localhost:8000/docs.

## Источники данных

Источник выбирается переменной `MI_SOURCE`:

| Значение | Что делает |
| --- | --- |
| `sandbox` (по умолчанию) | Детерминированный симулятор рынка по реальному списку из 103 артефактов. Нужен потому, что demo-API отдаёт одинаковые синтетические данные (10 лотов по 10 000 и несколько сделок по 1000), на которых аналитика пуста. |
| `demo` | Реальные HTTP-запросы к `https://dapi.stalcraft.net` с demo-токеном. |
| `production` | Реальные запросы к `https://eapi.stalcraft.net` с одобренным токеном приложения. |

Пример запуска на demo:

```bash
cd backend
MI_SOURCE=demo MI_API_TOKEN="<токен>" .venv/bin/uvicorn app.main:app --port 8000
```

Продакшн:

```bash
MI_SOURCE=production MI_API_BASE_URL=https://eapi.stalcraft.net MI_API_TOKEN="<токен>" \
  MI_REGION=RU .venv/bin/uvicorn app.main:app --port 8000
```

Токен нигде не хранится в коде: только переменная окружения или `backend/.env`
(файл в архив и в репозиторий не попадает).

## Настройки

Все параметры — переменные окружения с префиксом `MI_` (см. `backend/app/config.py`):
`MI_REGION`, `MI_REQUESTS_PER_MINUTE`, `MI_HOT_INTERVAL_SECONDS`, `MI_COMMISSION_PERCENT`,
`MI_MIN_PROFIT`, `MI_MIN_ROI_PERCENT`, `MI_HISTORY_WINDOW_HOURS` и другие.

Коллектор сканирует адаптивно: «горячие» артефакты (высокая ликвидность и цена) —
часто, остальные — реже, чтобы уложиться в лимит запросов API.

## Метрики

- **Рыночная цена** — медиана цены за штуку по завершённым сделкам в окне, после отсева
  выбросов методом MAD. Минимальный активный лот в расчёт не берётся.
- **Ликвидность** — среднее число проданных единиц в сутки.
- **Волатильность** — стандартное отклонение к средней цене.
- **Доверие** — размер выборки, свежесть последней сделки и разброс цен (0–100).
- **Вероятность продажи** — `1 - exp(-ликвидность × часы / 24)`.
- **Ожидаемая прибыль** — `прибыль × вероятность продажи × доверие`. По ней сортируется лента.

## Ограничения тестовой версии

- Авторизации нет: вотчлист и портфель общие для всех, без разделения по пользователям.
- SQLite и один процесс; для продакшна нужны PostgreSQL и отдельный процесс коллектора.
- Глубина истории растёт с момента запуска: API отдаёт только последние 200 сделок.
- Уведомлений в Telegram/Discord пока нет — интерфейс для них заложен, интеграция впереди.
